# 📖 Style Guide

> 🌐 Language: **English** | [فارسی](fa/style-guide.md)

> This document defines the writing, formatting, and educational standards for the Python Roadmap project.
>
> Every lesson, exercise, quiz, project, README, and document in this repository must follow these guidelines.

---

# 🎯 Purpose

The purpose of this guide is to ensure that the project remains:

- Consistent
- Beginner-friendly
- Easy to maintain
- Easy to contribute to
- Ready to become a book, website, or online course in the future

---

# 🌟 Project Philosophy

This project is built on one simple idea:

> **We teach programming by teaching thinking first, then syntax.**

Programming is more than writing code.

It is the process of understanding a problem, designing a solution, and finally implementing that solution.

Everything in this repository should help learners understand concepts—not memorize code.

---

# 🏆 Core Principles

## 1. Think Before You Code

Programming starts with thinking.

Every lesson should first answer:

- Why does this concept exist?
- What problem does it solve?

Only then should it explain the syntax.

---

## 2. Understand, Don't Memorize

Learners should understand ideas instead of memorizing code.

Whenever possible:

- Explain concepts using simple language.
- Use real-world analogies.
- Build intuition before introducing syntax.

---

## 3. Practice Is Part of Learning

Reading alone is not enough.

Every lesson should include practice.

Exercises are a required part of learning—not optional.

---

## 4. Quality Over Quantity

Our goal is not to create the largest Python roadmap.

Our goal is to create one of the best.

Every lesson should be:

- Clear
- Practical
- Beginner-friendly
- Timeless

---

# 👨‍🎓 Target Audience

This project is designed for:

- Complete beginners
- Self-taught developers
- Students
- Career changers
- Anyone learning Python from scratch

No programming knowledge should be assumed.

---

# ✍️ Writing Style

Content should be:

- Clear
- Friendly
- Professional
- Encouraging
- Easy to read

Avoid:

- Long paragraphs
- Complex wording
- Unnecessary technical jargon

Write as if you are teaching one person sitting next to you.

---

# 📚 Lesson Structure

Every lesson should follow the same structure.

## 1. Overview

Briefly introduce the topic.

---

## 2. Learning Objectives

Clearly explain what learners will be able to do after completing the lesson.

---

## 3. Concept Explanation

Explain the idea before writing code.

Answer:

- What?
- Why?
- When?

---

## 4. Examples

Provide practical examples.

Examples should teach one concept at a time.

---

## 5. How It Works

Explain the example line by line when necessary.

---

## 6. Common Mistakes

Show common beginner mistakes.

Explain:

- Why they happen
- How to fix them
- How to avoid them

---

## 7. Best Practices

Teach good habits from the beginning.

Readable code is more important than short code.

---

## 8. Exercises

Every lesson should include:

🟢 Basic

🟡 Intermediate

🔴 Challenge

Exercises should gradually increase in difficulty.

---

## 9. Quiz

Every lesson ends with a short quiz.

Questions should test understanding—not memorization.

---

## 10. Summary

Summarize the lesson in a few bullet points.

---

## 11. Next Lesson

Briefly introduce the next lesson.

---

# 💻 Code Style

All code examples must:

- Be tested before publishing.
- Follow PEP 8 whenever possible.
- Use meaningful variable names.
- Focus on one concept at a time.
- Be easy to read.

Avoid meaningless examples like:

```python
x = 5
y = 10
```

Prefer:

```python
width = 5
height = 10
```

---

# 🌍 Real-World Examples

Use examples learners can relate to.

Examples may include:

- Students
- Books
- Shopping
- Banking
- Products
- Employees
- Weather
- Temperatures
- Schools

Avoid unrealistic examples whenever possible.

---

# 📝 Exercises

Exercises should reinforce learning.

Progression:

🟢 Easy

Practice a single concept.

🟡 Medium

Combine multiple concepts.

🔴 Challenge

Require problem-solving.

---

# ❌ Common Mistakes

Every lesson should include common beginner mistakes.

Mistakes should be explained clearly.

Never assume learners know why something is wrong.

---

# 💡 Best Practices

Always teach professional habits.

Examples:

- Use descriptive variable names.
- Write readable code.
- Keep examples simple.
- Prefer clarity over cleverness.

---

# 🌐 Bilingual Content

English content is always written first.

Persian content should:

- Preserve meaning.
- Read naturally.
- Avoid literal translation.

The goal is communication—not word-for-word translation.

---

# 📄 Markdown Rules

Use consistent formatting across the project.

Always use:

- Headings
- Tables
- Lists
- Callouts
- Syntax-highlighted code blocks

Keep formatting clean and consistent.
